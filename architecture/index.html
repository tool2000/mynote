    AI는 똑똑해졌지만 LLM 구조는 거의 바뀌지 않았다. 이게 무엇을 의미할까? (25.8)

    문제 제기

    • GPT-2 공개 이후 Llama, Mistral, DeepSeek, Qwen 시리즈까지 이어져오고 있지만, 근본적으로 GPT 아키텍처에는 변함이 없었다.
    • 트랜스포머 구조는 여전히 공고한 산업 표준으로 자리잡고 있다.
    • 물론 포지셔널 임베딩 방식에서 절대 포지션 -> RoPE, NoPE 등으로의 변화가 있었다. 정말 위치 임베딩은 없어도 되는 것일까?
    • 요즘은 공히 전문가 계층(MoE)의 시대인 것 같다. 추론 속도 및 엔지니어링 측면(서버 운용)에서 확실한 잇점이 있다고 생각한다. 하지만 이게 최선일까? 나는 새로운 아키텍처의 흐름이 오면 바뀔 여지가 있다고 생각한다. 예컨대 latent reasoning 같은 변화들.
    • 정규화 레이어는 언제나 중요했다. 방식에서는 Normalization 에서 RMSNorm으로 변했고, PreNorm, PostNorm 등의 변화가 있었지만 근본적인 변화는 아니었다고 생각한다. 정규화 레이어는 필요한 순간에, 언제 어디서든 붙으면 좋은 거 아닐까? 내가 너무 단순화시켜 생각하는 것일까?
    • 트랜스포머가 아닌 다른 mamba 계열의 아키텍처에 대한 공부가 필요하다.

    Attention 계층의 변화

    • MHA(Multi Head Attention) : 멀티헤드어텐션
      • 트랜스포머 아키텍처에서 처음 소개된 오리지널 어텐션 레이어.
      • 어찌보면 가장 표준적이고 잘 작동하지만 연산량이 O(n ** 2) 으로 높은 어텐션
      • 트랜스포머 속도 병목의 주된 요인 중 하나
    • GQA(Grouped Query Attention) : 그룹쿼리 어텐션
      • 메모리를 절약하기 위해, 여러 헤드를 그룹화해서 그룹별로 동일한 KV 캐시를 공유한다.
      • 메모리 절약으론 성공적 전략이지만, ablation 테스트를 통해 MHA 방식과 비교해보았을 때 소폭 스코어 하락이 관찰됨(미미한 수준)
      • 긍정적으로 보면, MHA와 거의 유사한 성능을 내면서 메모리 사용은 대폭 절감시켜 주므로 학습 효율이나 속도면에서 이득. 지금도 여러 모델들이 채택하고 있다.
    • MLA(Multi-Head Latent Attention) : 멀티 헤드 잠재 어텐션
      • 2025년 초, 놀라움과 충격을 주었던 DeepSeek R1 추론 모델에 사용된 어텐션
      • 사실 R1 에서 처음 사용되었던 것은 아니고 DeepSeek V3 뿐만 아니라 무려 V2 에서도 사용되었다.
      • 이 기술은 어텐션에 사용되는 Q,K,V 세트 중 KV캐시를 저차원 공간으로 압축하여 소중한 메모리 사용량을 획기적으로 절감한다. (대신 행렬 곱셈이 추가되어야 하지만, 한정된 메모리 자원을 가진 팀에게 메모리 절약은 지상사명이었을 것이다.)
      • 이 기술을 사용했을 때, 토큰 당 KV Cache 사용량은 기존 MHA 방식 110k 에서 15k 정도로 거의 8배 가까이 절약할 수 있다.
      • 메모리를 절약할 뿐만 아니라, 거의 모든 벤치마크 결과에서 소폭 더 높은 성능을 보여줬다!
      • 이 정도면 MLA 를 안 사용할 이유를 찾기가 어렵지 않나라고 생각한다. 다만 실제 프락시 모델 훈련 실험에서 최종 판단을 해야할 것이다.
    • SWA(Sliding Window Attention) : 슬라이딩 윈도우 어텐션
      • 말그대로 어텐션하는 영역을 일정 윈도우 크기 안으로 제한하면서, 왼쪽에서 오른쪽으로 이동해 가는 것.
      • KV 캐시의 메모리 자원을 상당히 절약할 수 있다.
      • 이 테크닉은 GQA 와 MHA 와 동시에 사용될 수 있다.
      • 또한 슬라이딩 윈도우와 글로벌 윈도우를 일정 비율로 혼합해서 사용해도 된다.
      • 이런 복잡한 선택의 요소들 때문에, 모델 학습을 recipe 에 비유하는 것 같다.
    • 기타
      • Attention Bias/Sinks 테크닉에 대해서 알아보자. gpt-oss 모델에 이 오래된 테크닉이 쓰였다고 한다. OpenAI 가 이 테크닉에서 뭔가 새로운 걸 발견한 것일까?

    FFN 계층의 변화

    • Mixture-of-Experts (MoE) : 전문가 혼합 계층의 사용
      • 일단, '전문가'라는 용어 사용은 혼란을 불러일으킨다고 생각한다.
      • 좀 더 설명적으로 풀자면, FFN 레이어를 N개의 블록으로 나누고, 입력 토큰에 적합한 블록으로 토큰을 라우팅함으로써 좀 더 효율적으로 연산 프로세스를 개선했다고 말하는 것이 올바른 설명일 것이다.
      • 따라서 FFN 내에서 하나의 레이어가 옆으로 길어지더라도, 선택적으로 일부 블록만 선택하여 연산시킬 수 있으므로 더 빠르게, 더 싸게 연산할 수 있게 된 것이다.
      • 나는 개인적으로, 이러한 아이디어 자체가 혁신적이라고 생각하지는 않는다. 하지만, 매우 실용적이고 재치있는 접근이라 생각한다. 이 말은 다시 말해, 누구나 관심을 가지고 llm 아키텍처에 대해 연구하면 이처럼 실용적인 아이디어를 누구나 떠올릴 수 있고 추가할 수 있으며 따라서 성능 개선을 달성할 수 있다는 의미로 믿고 싶다.
    • Normalization Layer (정규화 레이어)
      • 정규화는 중요하다. 왜냐하면 정규화를 통해 데이터의 스케일링이 잘 이루어지기 때문이다.
      • 우리가 일반적으로 잘 알고, 트랜스포머의 오리지널 구조인 Layer Norm 이 요즘은 연산 상의 이점 때문에 거의 RMSNorm 으로 대체되는 느낌이다.
      • 정규화 레이어를 Attention 계층의 앞에 놓느냐 뒤에 놓느냐에 따라 Pre/Post Norm이라 하며, 앞뒤 둘 다 놓기도 한다.
      • 정규화 레이어를 이쪽 저쪽으로 옮겨서 테스트하는 이유는, 훈련 안정성을 높이기 위해서이다. 다시 말해, Loss Spike를 줄이기 위해서다.
      • QK-Norm 이라는 정규화 레이어도 있다. 다중 헤드 어텐션(MHA) 모듈 내부에 배치되어 쿼리(Q)와 키(K)에 적용된다.
    • Shared Layer (공유 레이어의 사용)
      • Gemma 3n 처럼 모델 가중치의 일부만 GPU 메모리에 로드하고, 토큰 계층별(텍스트, 오디오, 비전) 임베딩 레이어는 오프로딩함으로써 메모리 자원 절약 기법이 널리 사용되고 있다.
      • 이처럼 공유 가능한 레이어로 모델을 작고 독립적으로 분할하여 사용하면, 서버 운영 시에도 엔지니어링 측면의 이점을 크게 얻을 수 있다. (다시 말해, GPU 서버 메모리 크기에 맞춰서 모델을 분할 로드.. 예컨대 MoE 크기에 맞는 서버 구성 전략..)
      • MatFormer 논문도 참고.

    Positional Embedding (위치 임베딩) : 내 생각에, 추가 탐구가 필요한 영역

    • Absolute Positional Embedding. 트랜스포머 오리지날, 절대 위치 임베딩. 문장을 단번에 학습시키겠다는 목표를 위해 위치 임베딩이 필요하다고 생각했고, 위치 정보를 토큰 임베딩에 기입하겠다는 아이디어. 충분히 그럴 듯 하다.
    • RoPE. 회전 위치 임베딩. 토큰 위치를 기준으로 간단히 쿼리/키 벡터를 회전시켜 곱함으로써 위치 임베딩이 된다고 보는 테크닉. 아무튼 이걸로 우리는 128k 까지 수월하게 도달했다. 아참, YaRN의 도움도 있었지..
    • NoPE. 아예 위치 임베딩 정보를 빼 버리자는 것. 너무 놀라워서 당황스럽기까지한 주장이다. 근데 요즘 다시 화두가 되고 있다! 그러한 주장의 근거는 무엇인가? 지금의 LLM 구조 자체가 causal 이고 어텐션 마스킹 때문에 어차피 앞쪽 토큰들 밖에 볼 수 없으므로 굳이 위치 임베딩할 필요가 있느냐는 것. (그럼 여태까지 우리는 무엇을 했단 말인가.) 어쨌든 이러한 주장이 맞다면, 연산 부담 하나를 더 줄이고 구조를 단순화하는 효과를 얻을 듯하다.
    • The Impact of Positional Encoding on Length Generalization in Transformers(https://arxiv.org/abs/2305.19466 참고)

    Optimizer (옵티마이저)

    • 기존에는 대부분 AdamW 를 썼다.
    • 최근 kimi k2 시리즈에서 Muon 옵티마이저를 써서 훈련중 상당한 안정성을 얻었다는 것.
    • 테크니컬 리포트를 읽고 내가 이해한 바대로 간단히 말하자면, 기존까지 옵티마이저는 미분불가능해서 정규화가 안된다고 생각했는데, 행렬 연산 테크닉으로 정규화가 가능하다고 주장하는 것.
    • 그래서 훈련 중 스파이크 없이 안정적으로 수렴한다는 것인데.. 차트를 봤을땐 스파이크가 아예 없는 건 아닌데 상대적으로 안정되어 보이긴 한다.
    • 어쨌든 옵티마이저 부분에서도 아키텍처 상 혁신이 일어날 구석이 더 있다고 나는 믿고 싶다.
