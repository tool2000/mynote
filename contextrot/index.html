    컨텍스트 부패, 입력토큰의 증가가 LLM 성능에 미치는 영향

    문제 제기

    - long context 성능 평가는 주로 건초더미 속 바늘(NIAH) 테스트로 측정된다
- 그러나는 이는 간단한 어휘 검색 과제일뿐 요약이나 모호한 정보 처리에 대한 추론 능력까지 완벽한지는 의문이다
- 링크 : https://research.trychroma.com/context-rot

    long context 에서 llm 모델의 성능저하를 보여주는 benchmark

    - 어휘가 아닌 일치 항목이 있는 바늘-질문 쌍을 포함하는 NoLiMa 
- 주어진 텍스트 조각의 부재를 인식하는 모델을 테스트, AbsenceBench
- Michelangelo 벤치마크 : Latent Structure Queries(LSQ) 프레임워크 논문
    - 멀티턴에서 특정 질문의 i 번째 인스턴스를 검색하는 테스트(MRCR)
    - 가상의 Python 리스트에 **삽입·삭제·정렬**을 지시하는 프롬프트 성공률(Latent List)
    - 허구 이야기+무작위 문자열에서 답 찾기. I don't know 라고 말해야함 (IDK)
- Graphwalks 벤치마크 : 컨텍스트 전체를 **방향 그래프(edge list)** 로 채운 뒤, BFS 또는 부모노드를 찾는 능력을 테스트

    바늘-질문 유사성(Needle-Question Similarity)

    - 낮은 유사도의 바늘-질문 쌍을 사용하는 긴 문맥에서 성능이 더 빨리 저하(빨간선)
    ![[Pasted image 20250721192614.png]]
- 작은 모델(low performance)이고 바늘-질문 유사성이 낮으면 10k 부근에서 정확도 70% 수준
- 모델 크기에 상관없이 바늘-질문 유사성(약 0.8 전후)이 높으면 10k 부근에서도 90% 이상 방어

    방해 요소의 영향(Impact of Distractors)

    - 방해 문장 수가 늘어날수록 성능 곡선 기울기가 가팔라짐
- 잡음·중복·비슷한 문장까지 함께 주입하면 답이 틀릴 확률 급증
- ![[Pasted image 20250721202015.png]]
- 파란선: 방해요소 없음, 노란선: 방해요소 1개, 빨간선: 방해요소 4개
- context크기 500k 이하인 상위모델(high performance)의 경우, 방해요소 1개일때는 10k 수준에서 93% 정도이지만, 방해요소 4개일때는 10k 수준에서 65%로 급락.
- 500k 이하 작은 모델은 10k 수준에서 방해요소 4개일때 정확도 31%로 최하.
- 방해요소의 의미에 따라 하락률에 미치는 영향이 다름
- 클로드 모델은 일관되게 가장 낮은 환각률. 특히, 클로드 소네트 4와 오푸스 4는 특히 보수적이며, 불확실할 때 답을 찾을 수 없다고 명시적으로 언급하며 기권하는 경향. 이와 대조적으로, GPT 모델은 가장 높은 환각률을 보이며, 방해 요소가 있을 때 종종 확신은 있지만 잘못된 반응.

    바늘-건초더미 유사성(Needle-Haystack Similarity)

    - 에세이 건초더미에서 에세이 바늘찾기보다, 에세이 건초더미에서 arXiv 바늘찾기 정확도가 더 높았음. 장르가 다르면 더 찾기 쉽다는 가설 설정 가능하나, arxiv 건초더미에서 다른 바늘 찾기 정확도는 거의 같았고, 에세이보다 전체적으로 낮았음. 
- 전문 영역 건초더미에서 바늘 찾기가 어려울 수 있다는 가설 설정 가능(토큰 수 많아서?)

    건초더미 구조(Haystack Structure)

    - 논리적이고 구조적으로 일관성이 있는 건초더미와 셔플된 무작위 건초더미 중에서, 놀랍게도 모든 모델과 환경에서 **'무작위 건초더미'에서 바늘을 찾는 정확도가 5~8% 더 높았음**
- 이는 입력 구조(글의 논리적 순서)가 어텐션에 미치는 영향에 대한 해석 가능성 연구가 필요함을 의미
    - 다시 말해, 입력의 논리적 구조나 패턴은 어텐션 메커니즘 적용에 영향을 미침

    • LongMemEval 테스트

      • 긴 채팅 히스토리 컨텍스트가 제시되어 '관련 맥락을 찾는 단계'와 '대답을 위한 추론 단계'를 모두 만족시키는지 체크
      • 관련 맥락을 찾을 필요가 없는 '집중된 입력'(약 300 토큰)과 '전체 입력'(113k 토큰) 두 가지 조건에 대해서 모든 모델들이 '전체 입력'의 경우에 낮은 정확도를 보임. 클로드 opus 4 thinking은 '전체 입력'에 대해 약 23% 성능 하락, opus 4 는 정확도 92% -> 38%로 약 54%의 성능 하락
      • 그러나 구글 gemini 는 상대적으로 하락 방어율이 괜찮았음 (정확도 70~80% 정도)

    • 반복되는 단어 ( Repeated Words)

      • 문자열을 n번 반복하라는 간단한 작업에도 컨텍스트 길이가 길어짐에 따라 모델 성능이 균일하지 않음

    • 향후 추가연구

      • 긴 맥락을 다루는 애플리케이션이 합성이나 다단계 추론이 필요한 경우 성능 저하가 훨씬 더 심각할 것으로 예상
      • 추론 시점에 장문맥이 성능 저하를 보이지만, 훈련 시점에도 장문맥 데이터가 있으면 훈련 효율을 떨어뜨릴까?

    • 적용

      - 벤치마크의 자료구조는 역으로, 훈련 데이터를 어떻게 설계하고 수집할 것인가에 대한 기초 아이디어를 제공하기도 한다.
