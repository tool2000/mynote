    컨텍스트 부패, 입력토큰의 증가가 LLM 성능에 미치는 영향(25.7.14)

    문제 제기

    • long context 성능 평가는 주로 건초더미 속 바늘(NIAH) 테스트로 측정된다
    • 그러나 이는 간단한 어휘 검색 과제일뿐 요약이나 모호한 정보 처리에 대한 추론 능력까지 완벽한지는 의문이다
    • 링크 : https://research.trychroma.com/context-rot

    long context 에서 모델의 성능저하를 보여주는 benchmark

    • 어휘가 아닌 일치 항목이 있는 바늘-질문 쌍을 포함하는 NoLiMa
    • 주어진 텍스트 조각의 부재를 인식하는 모델을 테스트, AbsenceBench
    • Michelangelo 벤치마크 : Latent Structure Queries(LSQ) 프레임워크 논문
      • 멀티턴에서 특정 질문의 i 번째 인스턴스를 검색하는 테스트(MRCR)
      • 가상의 Python 리스트에 삽입·삭제·정렬을 지시하는 프롬프트 성공률(Latent List)
      • 허구 이야기+무작위 문자열에서 답 찾기. I don't know 라고 말해야함 (IDK)
    • Graphwalks 벤치마크 : 컨텍스트 전체를 방향 그래프(edge list) 로 채운 뒤, BFS 또는 부모노드를 찾는 능력을 테스트

    바늘-질문 유사성(Needle-Question Similarity)

    • 낮은 유사도의 바늘-질문 쌍을 사용하는 긴 문맥에서 성능이 더 빨리 저하(빨간선)
    • 작은 모델(low performance)이고 바늘-질문 유사성이 낮으면 10k 부근에서 정확도 70% 수준
    • 모델 크기에 상관없이 바늘-질문 유사성(약 0.8 전후)이 높으면 10k 부근에서도 90% 이상 방어

    방해 요소의 영향(Impact of Distractors)

    • 방해 문장 수가 늘어날수록 성능 곡선 기울기가 가팔라짐
    • 잡음·중복·비슷한 문장까지 함께 주입하면 답이 틀릴 확률 급증
    • 파란선: 방해요소 없음, 노란선: 방해요소 1개, 빨간선: 방해요소 4개
    • context크기 500k 이하인 상위모델(high performance)의 경우, 방해요소 1개일때는 10k 수준에서 93% 정도이지만, 방해요소 4개일때는 10k 수준에서 65%로 급락.
    • 500k 이하 작은 모델은 10k 수준에서 방해요소 4개일때 정확도 31%로 최하.
    • 방해요소의 의미에 따라 하락률에 미치는 영향이 다름
    • 클로드 모델은 일관되게 가장 낮은 환각률. 특히, 클로드 소네트 4와 오푸스 4는 특히 보수적이며, 불확실할 때 답을 찾을 수 없다고 명시적으로 언급하며 기권하는 경향. 이와 대조적으로, GPT 모델은 가장 높은 환각률을 보이며, 방해 요소가 있을 때 종종 확신은 있지만 잘못된 반응.

    바늘-건초더미 유사성(Needle-Haystack Similarity)

    • 에세이 건초더미에서 에세이 바늘찾기보다, 에세이 건초더미에서 arXiv 바늘찾기 정확도가 더 높았음. 장르가 다르면 더 찾기 쉽다는 가설 설정 가능하나, arxiv 건초더미에서 다른 바늘 찾기 정확도는 거의 같았고, 에세이보다 전체적으로 낮았음.
    • 전문 영역 건초더미에서 바늘 찾기가 어려울 수 있다는 가설 설정 가능(토큰 수 많아서?)

    건초더미 구조(Haystack Structure)

    • 논리적이고 구조적으로 일관성이 있는 건초더미와 셔플된 무작위 건초더미 중에서, 놀랍게도 모든 모델과 환경에서 '무작위 건초더미'에서 바늘을 찾는 정확도가 5~8% 더 높았음
    • 이는 입력 구조(글의 논리적 순서)가 어텐션에 미치는 영향에 대한 해석 가능성 연구가 필요함을 의미
      • 다시 말해, 입력의 논리적 구조나 패턴은 어텐션 메커니즘 적용에 영향을 미침

    LongMemEval 테스트

    • 긴 채팅 히스토리 컨텍스트가 제시되어 '관련 맥락을 찾는 단계'와 '대답을 위한 추론 단계'를 모두 만족시키는지 체크
    • 관련 맥락을 찾을 필요가 없는 '집중된 입력'(약 300 토큰)과 '전체 입력'(113k 토큰) 두 가지 조건에 대해서 모든 모델들이 '전체 입력'의 경우에 낮은 정확도를 보임. 클로드 opus 4 thinking은 '전체 입력'에 대해 약 23% 성능 하락, opus 4 는 정확도 92% -> 38%로 약 54%의 성능 하락
    • 그러나 구글 gemini 는 상대적으로 하락 방어율이 괜찮았음 (정확도 70~80% 정도)

    반복되는 단어(Repeated Words)

    • 문자열을 n번 반복하라는 간단한 작업에도 컨텍스트 길이가 길어짐에 따라 모델 성능이 균일하지 않음

    내 생각정리

    • 긴 맥락을 다루는 애플리케이션이 합성이나 다단계 추론이 필요한 경우 성능 저하가 훨씬 더 심각할 것으로 예상
    • 추론 시점에 장문맥이 성능 저하를 보이지만, 훈련 시점에도 장문맥 데이터가 있으면 훈련 효율을 떨어뜨릴까?
    • 벤치마크의 자료구조는 역으로, 훈련 데이터를 어떻게 설계하고 수집할 것인가에 대한 기초 아이디어를 제공하기도 한다.

    Long Context Benchmark : Ruler

    RULER 란 무엇인가

    • 무엇? “내 모델이 진짜로 쓸 수 있는 컨텍스트 길이는 얼마인가?”를 가늠하려고 만든 롱 컨텍스트 벤치마크. 엔비디아 연구진이 2024년 4월 공개했고(최신 v3: 2024-08-06), 코드/데이터를 오픈소스로 배포합니다. (arXiv)
    • 왜? 흔한 Needle-in-a-Haystack(NIAH) 같은 단순 검색(needle 찾기) 테스트만으로는 긴 문맥 이해를 충분히 측정하지 못하기 때문입니다. RULER는 검색을 넘는 과제들까지 포함해 더 종합적으로 평가합니다. (ar5iv)

    무엇을 어떻게 측정하나

    RULER는 4개 카테고리, 13개 대표 과제(길이·난이도 조절 가능)로 구성됩니다. 각 길이(4K, 8K, 16K, 32K, 64K, 128K 토큰)에 대해 예제를 대량 생성해 측정해요. (ar5iv)

    1. Retrieval(검색): 고전 NIAH/패스키/라인/키-값 검색을 확장해 needle의 종류·개수를 바꿔가며 회복력까지 확인(예: UUID처럼 긴 문자열 회수). (ar5iv)
    2. Multi-hop Tracing(다단 추적): 변수 추적 과제로 여러 홉에 걸친 연결/지시어를 따라가며 올바른 엔티티를 찾아냅니다. (ar5iv)
    3. Aggregation(집계): 긴 문맥에 흩어진 정보를 모아 공통/빈출 단어 추출 등 요약의 기초 능력을 봅니다. (ar5iv)
    4. QA(질문응답): SQuAD/HotpotQA 등에 방해 문서를 대량 주입해 긴 문맥에서도 정확히 근거를 찾아 답할 수 있는지 확인합니다. (ar5iv)

    평가 지표/프로토콜

    • 각 길이별로 예제 500개 생성 → **정답 토큰의 존재 여부(리콜 기반 정확도)**로 채점(답 회피 방지를 위해 답안 접두어를 함께 제공). (ar5iv)
    • Effective Context Size(실효 컨텍스트 길이): Llama-2-7B가 **4K에서 낸 점수(85.6%)**를 기준선으로 두고, 평균 점수가 이 기준을 넘는 최장 길이를 “실효 길이”로 정의합니다. 또한 길이별 성능을 가중 평균(짧은 쪽/긴 쪽 가중 시나리오)으로도 비교합니다. (ar5iv, GitHub)

    주요 관찰(요지)

    • 길이가 늘수록 대부분 급격히 성능 저하: 단순 NIAH는 거의 만점이지만, 다단 추적/집계/방해가 섞이면 길이 증가에 따라 급락합니다. **주장(context claim)**보다 실효 길이가 짧은 경우가 흔합니다. (ar5iv)
    • 모델 크기와 포지셔널 세팅의 영향: 큰 모델이 전반적으로 유리하고, RoPE 등 위치 임베딩 설정·길이 학습 방식에 따라 장거리에서 급추락(엑스트라폴레이션 실패)이 나타납니다. (ar5iv)

    현재(2025) 공개 스코어보드 스냅샷

    RULER 깃허브 README에는 최신 모델들의 실효 길이/가중 평균 점수가 꾸준히 업데이트됩니다(“살아있는” 표이므로 일부는 저자 보고치). 예시:

    • Jamba-1.5-Large·Gemini-1.5-Pro: >128K에서도 높은 평균(≈96 전후).
    • GPT-4-1106-preview: 실효 64K로 보고.
    • 여러 Qwen3 / 2.5 / EXAONE 4.0 등 최신 모델들이 128K 이상에서 강세. (상세 표와 주석은 레포 README 참고) (GitHub)

    다른 벤치마크와 차이

    • RULER: 전부 합성(synthetic) → 길이/난이도 정밀 제어, 파라메트릭 지식 영향 최소화.
    • LongBench / L-Eval / ZeroSCROLLS / BAMBOO / InfiniteBench 등은 현실/혼합 과제 비중이 커 다양성은 높지만 길이·난이도 통제가 상대적으로 어렵습니다(표로 비교). (ar5iv)

    한계와 확장

    • 합성 위주라서 “현실적 사용”을 전부 대체하진 못합니다(저자들도 한계로 명시). 현실 과제(긴 문서 요약/검색·도구연계)와 보완적으로 쓰는 게 좋습니다. (GitHub)
    • 다국어 확장: 2025년 공개된 ONERULER는 RULER를 26개 언어로 확장(검색·집계·“정답 없음” 변형 등). 다국어/교차언어 긴 문맥에서 격차가 커짐을 보고합니다. (arXiv)
